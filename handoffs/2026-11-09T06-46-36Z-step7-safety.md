    - **Keeping a pass fresh** (decided 2026-11-09). Enable from a `PreflightPassed` in the tick it's made. Drop it, or
      cancel the enable sequence, on any event that voids it: a stop, a fault, silence, a drop out of Run, bus loss, a
      reboot or runtime restart, or a write from elsewhere. An ordinary reply doesn't void it. Run preflight again for
      every enable. Test cancellation before the hand-off, mid-sequence, across stop and clear, and while other named
      joints wait.

      echo would hide the sequence's own.
    - **Every named joint's preflight finishes before the first Enable.** `can` refuses slow writes to a limb that
      isn't idle (`SlowRefusal::LimbNotIdle`).
    - **A failure after `Enabling::enable_planned()` stops the limb**; a failure before it only refuses.

## The step 7 design (agreed with Joey 2026-11-08; not written down anywhere else)

- **D1, two places check.** The control thread decides everything that needs joints, limbs or the skeleton. The bus
  thread vetoes before every send, on what it has just drained: a fault bit, a mode other than Run on an enabled drive,
  or too many missed replies. Any of these stops that drive's limb at once and sends it nothing this tick. These stop
  reasons live in `can`; `safety` maps them to rule IDs (`RuleId::of_stop`). One schedule origin is shared by every bus
  thread and the control thread. Control publishes the batch for tick n+1 by a set phase of tick n.
- **D2, limb stops live in the bus layer.** A stop is scoped to one limb's slot group: Disable re-sent until each drive
  confirms, reporting off after the silence, an outcome per drive, latched. A whole-bus stop is every group. Control
  asks for a stop with `stop(group, reason)`, never with Disables in a batch. The operator's clear re-arms a group in
  place, only when every drive is confirmed in Reset or silent past the timeout; it starts a new fault-history
  generation and needs fresh preflights. A bus error re-arms only by rebuilding the bus thread after a clear.
- **D3, slow requests.** One slow exchange in flight per bus, in the slack after the collect deadline, until the real
  adapter is measured. Reads are matched by the type-17 reply naming their register, get-ID by the type-0 reply. A
  write is answered by a plain status that names no register, so preflight reads every write back. Requests time out
  and are never retried by `can`. They are refused for stopping or stopped limbs and cancelled when control goes
  silent.
- **Acceptance:** every rule row gets its own expected outcome in the sim. `host.pi_health` and the sign check can't be
  simulated on `vcan`; they go to steps 8 and 9.

## How the work has been done

- **Branches and PRs**, stacked; Joey merges. Commits and PR bodies describe the change only (conventions/git.md).
- **Test first.** Every test has a `Guards:` line and asserts exact values (conventions/testing.md). After each change,
  mutation-check the guards: each mutation of a rule must make a test fail.
- **Checks:** `cargo clippy --all-targets -- -D warnings`, `cargo test`, `python3 scripts/check_rules.py`, then
  `scripts/devbox.sh run ./scripts/check.sh` and `./scripts/sim.sh` on the Linux dev box (docs/dev-box.md). The
  realtime crates (`can`, `robstride`, `safety`) carry `#![warn(clippy::wildcard_enum_match_arm, clippy::as_conversions)]`
  and a `clippy.toml` that bans `Instant::now`, `sleep`, `mpsc` and `catch_unwind`; `control` and the realtime parts of
  `runtime` need the same.
- **Review:** each PR got a multi-model review (Joey's `joe-review` skill); the findings were triaged, fixed and scored.
  For one-off design questions to Sol, use medium effort, not xhigh.

## Open questions held for the hardware

- When a drive's Reset reply to a Disable arrives: straight away, or only after the post-Disable silence (up to
  48.7 ms)? `can::BusTick` sends reporting-off 50 ms after the confirmation, inside a 100 ms stop window, so a late
  reply would push reporting-off out of the window. Measure it on the bench when Joey says go; don't change the window
  before then.
- Whether the three caps bound MIT mode at all (PLAN `drive.caps` caveat): the caps-in-mode test is in step 8.
- A commissioning pulse for the sign check would need a rule change to the tenets and PLAN. Today null `direction` or
  `zero_rad` refuses enable (`Refusal::FactUnset`).

**Real hardware rule:** no Enable, motion, Set Zero, set-ID or parameter write to a real drive unless Joey is present and
has said go for that session. `vcan` is always fine.
